# 金手指面板与插件体系

## 1. 自动暴露是怎么做的

游戏在 `create()` 里调 `ctx.cheats.declare(...)`，平台把声明收进 `CheatStore`。系统菜单（HUD 上的「金手指」按钮，或手柄 `start+select` 长按）打开面板时，直接读 `session.cheats` 渲染。

**平台侧没有写死任何一条金手指。** 游戏声明三条就显示三条，声明十条就显示十条。测试里这条是硬断言：

```
游戏声明了 move-speed / giant-cursor / unlock-all-colors
面板打开后 .cheat-row 必须正好是 3
```

两种声明形态自动映射成两种控件：

| 声明 | 控件 |
|---|---|
| `kind: 'boolean'` | 复选框 |
| `kind: 'number'` | 滑杆，范围与步进来自 `min`/`max`/`step` |

改值走 `session.setCheat(id, value)`，平台侧再夹一次（浏览器 range 已经夹过，但 API 调用方可能绕过 UI）。

## 2. 注入权限：现在做不到，别假装能做

你提的「只有模拟器能注入，游戏在别的平台打开时不能注入」——**在纯 Web 环境下无法实现**。

原因很直接：游戏代码在浏览器里跑，它调自己的函数不需要任何许可。就算平台在 `ctx.cheats` 上做手脚，游戏作者完全可以绕开 `ctx` 直接改内部变量。

能做的是**降低误用**，不是**阻止注入**：

- 金手指状态存在平台自己的 IndexedDB 库里，游戏代码读不到别的游戏的
- `ctx.cheats` 是只读接口（`enabled` / `value` / `declare`），游戏无法自己改状态
- 平台侧 `setCheat` 是唯一写入口

**这是"约定 + 便利"，不是"安全边界"。** 文档里必须这么写，否则以后有人会以为它是安全机制。

真正需要强隔离的时候（比如第三方不可信游戏），路是 iframe 沙箱 + postMessage，见 `architecture.md` 第 7 节。那是 v2 的事，且代价很大（帧数据跨进程传输）。

## 3. 插件体系：金手指是第一个插件，但不是唯一

你的直觉是对的：**金手指本质上是一个可选能力**——没有它游戏照样能玩。

但"插件"这个词在这里要小心。传统插件（DeepSeek / OpenAI 那种）有两个特征：

1. **运行时加载**：平台不认识它，从外部拿来就能用
2. **双向约定**：平台调插件，插件也回调平台

金手指只满足第 2 条的一半：它是**游戏自己声明**的，平台不认识也不需要认识具体内容。这更像**「能力声明」**，不是「插件加载」。

### 三类东西，别混成一个机制

| 类型 | 谁提供 | 谁消费 | 例子 |
|---|---|---|---|
| **能力声明** | 游戏 | 平台渲染 UI | 金手指、设置项、成就定义 |
| **平台扩展** | 第三方 | 平台调用 | 新的输入源、新的存储后端 |
| **内容包** | 第三方 | 游戏自己加载 | 关卡包、MOD |

金手指属于第一类。硬套第二类的机制（动态 import、注册表、生命周期）只会带来复杂度，收益是零——因为游戏代码本来就在平台进程里跑。

### 现在该做的：把第一类做扎实

统一成一种声明形态，让平台能自动渲染：

```ts
ctx.declare({
  kind: 'number',      // boolean | number | enum
  id: 'move-speed',
  name: '移动速度',
  min: 1, max: 3, step: 0.25, defaultValue: 1,
  scope: 'cheat',      // cheat | setting | ...
});
```

`scope` 决定它出现在哪个面板：

- `cheat` → 金手指面板
- `setting` → 游戏设置（音量、按键）
- 未来 `achievement` → 成就列表

**这样加一种新的"可选能力"不需要动平台代码。** 这是真正的扩展性，而且不需要引入插件运行时。

### 什么时候才需要第二类

等到有「第三方写的输入源」或「第三方存储后端」时再说。那时的形态是：

```ts
// 平台提供注册点
host.registerInputSource(factory);
```

**不要提前做。** 现在没有第二个实现，接口形状只能靠猜，猜错的接口比没有更糟。

## 4. 这个面板现在的位置

- 入口：游戏运行时右上角 HUD 的「金手指」按钮
- 手柄：`start + select` 长按 1 秒（已有机制，走 `onSystemMenu`）
- 关闭：面板里的「关闭」按钮，或 Esc
- 打开时游戏暂停，关闭时恢复

**还没做的**：面板里的手柄焦点导航。现在只能用鼠标点，或键盘 Tab。M3 会补上空间焦点算法（见 `decisions.md` D10）。

在电视上这确实是硬伤，因为电视没有鼠标。M3 之前，建议先用键盘操作，或者在开发时用 PC。
